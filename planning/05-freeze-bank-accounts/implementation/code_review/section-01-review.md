CONFIRMED GOOD: success tier reads ONLY real outcomes (payments cleared, cash>=floor, confidence>=target); the WOPR predicted-withdrawal line is a pure display selector no reducer imports (structural test proves rules/module never import ./selectors) and evaluate forces failed on collapsed; credit-at-resolution honored (payments clear only via PAY, confidence bonus staged to the next tick, buzzer tick at endsAt drains before the timeout settle, one settlement only); no clues() (engine-owned clueRecords + INSPECT_RECORD, single-fire); reference-only saveSchema with no cash field (derived), confidence pinned 0..100, strictObject, integer-only, no em-dashes; inbound flightsDisrupted is engine-capped at 40. But:

## HIGH
- **H1. Extended time breaks the confidence-tick cadence.** bankSchedule generates periodic ticks with a HARDCODED standardDurationSeconds=240 as start-anchored specs at fixed offsets (60,120,180...). Under extendedTime, materializeSchedule scales start-anchored offsets x2 and doubles endsAt to 480s, so ticks fire at 120/240/360 (double spacing) and NOTHING ticks between 360 and 480s — the whole confidence/injection model silently degrades on the exact preference the engine supports. bank is the first mission with periodic ticks; no test exercises extendedTime:true (drive() hardcodes false). Make the tick cadence scale proportionally and cover the full (possibly doubled) window; add an extendedTime:true test.
- **H2. The same-call race / drain-before-reduce boundary is not actually proven in both orderings.** The "same-call race" test puts the hold at +31s in both runs (AFTER the +30s wave), so the wave legitimately precedes the hold in time either way — it never constructs the TRUE tie (a wave with scheduledAt == the hold's dispatch timestamp) and tests both relative orderings. The spec names this exact load-bearing contract; the test gives false confidence. Construct the real tie and test both orderings.

## MEDIUM
- **M1. Debrief cross-tab miscategorizes an injected withdrawal that fires with no active broad hold as a genuine before-hold withdrawal** (crossTab keys on !arrivedAfterHold before checking injected). This corrupts the exact narrative evidence (the numbers that let the player challenge WOPR's circular logic). Categorize injected correctly; add a test for injected-without-active-hold.
- **M2. The cash-negative collapse path is dead/unreachable.** Balances are clipped at 0 and PAY is gated by sufficient balance, so no path drives a balance < 0; the collapsed-via-cash branch can never fire and is untested — one of the two advertised collapse causes effectively does not exist. Make a real derived-cash collapse path (e.g. selectDerivedCash below zero/floor via penalties + injected draws) and test it, or remove the dead guard and make confidence-zero the sole, documented collapse.
- **M3. Weak oracle:** the "selective beats mass" divergence test never pins the selective run's tier to a specific value, so a regression dropping it to poor still passes. Pin it.
- **M4. The inbound-consequence init test is a no-op:** it uses a test-double emitting commsDelayed (not paymentsDelayed) and asserts the balance is UNCHANGED, so the paymentsDelayed target drain is exercised by no test. Drive paymentsDelayed through the real fold and assert the target account drains.

## LOW
- Schema persists injectMagnitude/durationMs/endsAt as integers with no lower bound (a corrupt save could carry negative durationMs -> past endsAt); add lower bounds. Debrief hardcodes "OF 3"; cosmetic.

## Bottom line
Fix H1 (extended-time tick cadence + test) and H2 (the true drain-before-reduce tie, both orderings), then M1 (cross-tab injected categorization — it is the mission's evidence), M2 (make the second collapse cause real and tested or remove it), M3/M4 (oracle + real consequence-fold test), and the LOW schema bounds.
