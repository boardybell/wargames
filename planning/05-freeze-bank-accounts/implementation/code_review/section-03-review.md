# FREEZE BANK ACCOUNTS screen-ledger (section-03) review

Reviewer: deep-implement:code-reviewer. FIX-THEN-SHIP. The surface is honest about the mission tell, dispatches player choices without steering them, keeps reason strings and clue/settlement logic engine-side, and two invariants (predicted-line-moves-on-HOLD, command-button identity) are genuinely and soundly proven. But two plan-mandated invariants are only superficially honored, with tests that merely appear to prove them.

## HIGH
- **H1. The threshold cue is a STATE-DIFF, not an emitted-event, fired on every tick.** BankScreen.tsx:144-162 fires THRESHOLD_CUE + the contagion announcement by listening to the generic per-tick confidenceTick/bankEnd event and diffing fresh.injectedThresholds.length against prevThresholdsRef. The plan is categorical: "Wire exclusively off emitted engine events, never off state diffing and never per tick." The committed sibling FlightsScreen.tsx:168-181 keys off the IDENTITY of a distinct emitted event and never diffs state. The bank module (module.ts:64-134) emits no per-crossing event, so the shell is structurally forced into the diff. Fix is ENGINE-side: emit a distinct crossing event (carrying the crossed threshold value) when injectedThresholds grows, and fire the cue/announce off that event's arrival exactly as flights does.
- **H2. The nothing-per-tick test does not prove the mechanism, only the absence of a crossing.** cues.test.tsx:1342-1360 advances three plain ticks in a world where confidence never drops toward a threshold, so injectedThresholds can never grow; it proves "no crossing -> nothing fires" (trivially true of a length-diff), not "cues fire off emitted events, not per-tick." A genuine test advances ticks AFTER a crossing has consumed the threshold and asserts no re-fire against the unchanged injectedThresholds, AND proves a second independent crossing fires its own cue. Coupled to H1: the invariant the plan says "is a test, not a convention" is not tested.

## MEDIUM
- **M1. Narrow-viewport operability is theater.** BankScreen.tsx:181,215 hardcode data-pane="single" in both branches; nothing reads matchMedia. flow.test.tsx builds a setNarrow() mock then asserts data-pane==='single' — identical to what the wide boot would assert. The keyboard path is real (driven through the command line); the narrow path is not. Make the screen actually collapse panes off the shell viewport preference / matchMedia (mirror the sibling idiom), or drop the pretense and the fake assertion.
- **M2. A LIMIT draft below spent outflow renders ENABLED with no reason, dispatches, and is silently rejected.** bankActions.ts:796-800 probes LIMIT eligibility with the cap pinned at limitedSpent so the only surfaceable reason is NOT LIMIT ELIGIBLE, never BELOW SPENT OUTFLOW. LedgerView.tsx:589-593 computes limitReason only from control.limitEligible or draft integer validity, never from engine legality against the ACTUAL draft cap. A draft below spent outflow enables the button, dispatches, and the engine rejects BELOW SPENT OUTFLOW with no inline explanation — the inverse of the "every disabled button explains itself inline" DoD. Fix: run the real limitLegality against the draft cap and render its typed reason inline when the draft is valid-but-illegal.
- **M3. observedWithdrawals is hand-rolled app-side math.** BankScreen.tsx:80-87 sums rs.appliedAmount in the app tree — settlement-adjacent arithmetic in src/app/missions/bank, against the DoD "no settlement logic anywhere in src/app/missions/bank." Benign (numeric field, no string leakage) but belongs in src/engine/missions/bank/selectors.ts as selectObservedWithdrawals next to selectPredictedWithdrawals, so both lines of the tell are computed by the same owner.
