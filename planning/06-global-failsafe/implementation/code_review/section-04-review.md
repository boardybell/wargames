## HIGH
- **H1. The ending is unreachable through ScreenRouter.** The engine settles the finale like any mission: settle() changes phase to 'debrief' with no finale special-case, so ScreenRouter.screenIdForState returns 'debrief' and renders the generic DebriefScreen ("DEBRIEF: FINALE TIER FULL" + ACKNOWLEDGE), never EndingScreen. FinaleScreen's own `if (settled) return <EndingScreen/>` short-circuit is dead because the phase has already left 'mission'. Every ending "proof" bypasses this seam: integration.test.tsx mounts <FinaleScreen> directly (its header admits "which the ScreenRouter (debrief phase) would otherwise replace"), ending.test.tsx mounts <EndingScreen> directly, no test drives COMMIT through ScreenRouter. FIX (in scope to close split 06): route a settled-but-unacknowledged FINALE to EndingScreen — either a ScreenRouter branch (when the pending debrief's missionId is the finale, render EndingScreen instead of DebriefScreen) or an engine finale/ended phase mapped to EndingScreen — and add a ScreenRouter-driven test that registers the finale screen, commits, and asserts data-testid='finale-ending' renders without a direct mount. Provide a registerFinaleScreen() callable.
  - NOTE (deferred to split 08, not a section-04 miss): nothing in src/ calls any register*Screen() and main.tsx mounts the standalone WarGamesGame tribute, so NO engine-backed mission screen renders in the shipped binary yet. ## MEDIUM
- **M1. Keyboard-only COMMIT bypasses the confirmation dialog**, so the typed path and button path are NOT identical at the one irreversible action (a keyboard user commits the finale with no confirm; a mouse user gets one). Route typed COMMIT through the same confirmation gate (dispatch opens the dialog, Enter confirms), or document that typed COMMIT is intentionally un-gated — but do not claim full command-button parity while COMMIT diverges. Prefer gating it.
- **M2. EndingScreen reconstructs proved-slots from a single flag.** finaleStateFromOutcome fabricates a finale state on return-nav (engine deleted the substate), stamping every slot 'x' when case_valid==1; deriveEarnedWhy then reads provedSlots from this synthetic reconstruction, so the "proved evidence" readback is inferred from a boolean, not what the player actually proved. Coincidentally matches the happy path but can disagree. FIX: persist the real proved-slot list into the finale SettledOutcome metrics at evaluate() (one bit per slot) and read those in EndingScreen.
