## HIGH
- **H1. The REQUEST FIELD REPORT bounded-wait is asserted, not enforced.** The module has ZERO knowledge of a decision margin or the field-report desk delay (no FINALE_DECISION_MARGIN / durationMs-minus-margin check anywhere in src/engine/missions/finale). The fieldReport "slack" test passes only because the fixture hand-picked deskCheck delaySeconds=20 against a hand-authored 60s margin. Amendment 12 / the plan (lines 54-56, 127) require the authored wait to be validator-bounded to finaleDuration minus a decision margin. As built, a seed author could write a 170s desk delay against a 180s finale and REQUEST FIELD REPORT would stall the player past the commit window — unprevented. Fix: enforce the bound at construction / seed-validation (the designated field-report record's authored deskCheck delay <= durationMs - DECISION_MARGIN, raise on violation), with a test that a violating seed is rejected. If this genuinely belongs to section 04, amend the plan's "this section owns the bounded wait" claim and done-when — but prefer building it here.

## MEDIUM

FinaleState carries dead, engine-duplicated deadline truth.** types.ts adds durationMs + endsAt; the plan's verbatim FinaleState has neither, and terminal() reads ONLY state.committed — nothing reads state.endsAt/durationMs. The engine already owns the authoritative deadline at activeMission.endsAt. Delete durationMs/endsAt from FinaleState, its saveSchema, init, stampDeadline, and both test emptyState helpers; read activeMission.endsAt through the selector seam if ever needed.
- **M2. recognitionFired is off-contract persisted state consumed by nothing in this section.** The plan says the recognition beat IS the caseValid false-to-true transition the shell keys on; it does not call for a persisted latch. Either document why it must survive save/load (and confirm a mid-finale reload should NOT re-permit the beat), or derive it instead of persisting.
- **M3. The ordering rejection miscodes incomplete coverage as receipt-order.** caseBuilder returns { code:'receipt-order', slot:'outlook' } whenever ordering does not cover the three subsystem ids, but receipt-order specifically means the receipt-vs-event-time inbox illusion; a short/malformed ordering is structurally incomplete, not a receipt sort. Section 03 will author wrong text for this path. Fix: guarantee ordering structurally covers the three slots before validate (make the branch an invariant throw), or map incomplete-ordering to 'incomplete' naming the empty subsystem.
- **M4. BROKEN_CHAIN reads silently as unrelated-source.** isIndependentObservation can return BROKEN_CHAIN (cyclic/orphaned parent), but the classifier only treats DERIVED_ORIGIN/DIRECT_RUN_STAMP/ANCESTRY_TOUCHES_RUN as derived-not-independent, so a corrupted derivative rejects as unrelated-source, untested. Decide the intended code and add a fixture.
